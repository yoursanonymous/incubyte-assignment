# Data model (PostgreSQL 16, managed by Prisma migrations)

All tables use snake_case names via `@@map`/`@map`. IDs are UUIDs generated by the database (`gen_random_uuid()`). Timestamps are `timestamptz`.

## users

| column                 | type                                                                       | notes                                         |
| ---------------------- | -------------------------------------------------------------------------- | --------------------------------------------- |
| id                     | uuid PK                                                                    |                                               |
| email                  | citext-like: `text` **UNIQUE**, stored trimmed + lowercased by the service | CHECK `email = lower(email)`                  |
| password_hash          | text                                                                       | Argon2id PHC string; never returned           |
| role                   | enum `Role` (`CUSTOMER`,`ADMIN`)                                           | default CUSTOMER; not settable via public API |
| status                 | enum `UserStatus` (`ACTIVE`,`DISABLED`)                                    | default ACTIVE                                |
| created_at, updated_at | timestamptz                                                                |                                               |

## vehicles

| column                 | type                   | notes                                                        |
| ---------------------- | ---------------------- | ------------------------------------------------------------ |
| id                     | uuid PK                |                                                              |
| make, model            | varchar(60)            | trimmed, 1–60 chars                                          |
| category               | enum `VehicleCategory` | SEDAN, SUV, TRUCK, COUPE, HATCHBACK, CONVERTIBLE, VAN, WAGON |
| price_cents            | integer                | CHECK `> 0 AND <= 1_000_000_000` (≤ $10 M)                   |
| quantity               | integer                | CHECK `>= 0 AND <= 100000`                                   |
| archived_at            | timestamptz null       | soft delete                                                  |
| created_at, updated_at | timestamptz            |                                                              |

Indexes: `(archived_at, make, model, id)` for the default ordered listing; `(category)`; `(price_cents)`; `(lower(make))`/`(lower(model))` are not added until profiling shows ILIKE cost matters at real data sizes.

## purchases

`id uuid PK`, `user_id → users(id) ON DELETE RESTRICT`, `vehicle_id → vehicles(id) ON DELETE RESTRICT`, `quantity int CHECK (1..10)`, `unit_price_cents int CHECK > 0`, `total_cents bigint CHECK = unit_price_cents::bigint * quantity`, `created_at`. No status column: a purchase either committed or does not exist (refunds/cancellations are out of scope; adding a status without a defined lifecycle was explicitly discouraged). Indexes: `(user_id, created_at DESC)`, `(vehicle_id)`.

## idempotency_keys

`user_id → users`, `key varchar(128)`, `operation varchar(40)` (`PURCHASE`), `request_hash char(64)` (SHA-256 of vehicle id + quantity), `purchase_id → purchases`, `response_status int`, `response_body jsonb`, `created_at`. **PK `(user_id, operation, key)`**. The row is inserted in the _same transaction_ as the purchase. Concurrent reuse blocks on the PK until the first transaction ends, then sees the committed row and replays its response. If the purchase fails the transaction rolls back and the key is not consumed (failures are not replayed; the retry is re-evaluated against current stock). Rows older than 24 h may be purged by a maintenance job _(documented, not scheduled)_.

## refresh_tokens

`id uuid PK`, `user_id → users ON DELETE CASCADE` (sessions, not business records), `family_id uuid`, `token_hash char(64) UNIQUE` (SHA-256), `expires_at`, `used_at null`, `revoked_at null`, `created_at`. Rotation sets `used_at` and inserts a child in the same family. Presenting a token with `used_at` set ⇒ replay ⇒ revoke all tokens in the family. Index `(family_id)`, `(user_id)`.

## audit_events

`id uuid PK`, `actor_id → users ON DELETE SET NULL`, `action varchar(60)` (e.g. `VEHICLE_CREATED`, `VEHICLE_UPDATED`, `VEHICLE_ARCHIVED`, `VEHICLE_RESTOCKED`, `USER_LOGIN_FAILED`? — _not_ recorded; see security.md), `target_type`, `target_id`, `metadata jsonb` (changed field names and numeric deltas only; never secrets), `created_at`. Append-only by convention; the app role has no UPDATE/DELETE grant planned for production _(documented)_.

## Migrations

Versioned SQL migrations in `backend/prisma/migrations`, applied with `prisma migrate deploy` (never `db push`/`migrate reset` outside local dev). Hand-written SQL appended to the initial migration adds the CHECK constraints Prisma cannot express. Backups: `pg_dump --format=custom`; restore with `pg_restore --clean --if-exists` into an empty database, then `prisma migrate deploy` to confirm no drift.
